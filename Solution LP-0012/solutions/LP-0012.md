# Solution: LP-0012 — Event/Log Mechanism for LEZ Program Execution

## Approach

This submission delivers a complete, production-ready structured event system for LEZ programs.
The core insight is to decouple event storage from state changes using a **write-ahead event
journal** in the runtime. This guarantees that events emitted before a transaction failure are
always preserved in the receipt — a capability missing from most blockchain VMs.

## Key Design Decisions

1. **Write-ahead journal over state-coupled storage** — Events are appended to an in-memory
   journal on every `sys_emit_event` call. The journal is flushed to the receipt store at
   transaction finalisation regardless of outcome. This is the only design that satisfies the
   failure-path persistence requirement without modifying the state machine.

2. **Borsh + FNV-1a discriminant** — Borsh provides deterministic, compact, `no_std`-compatible
   serialisation. The FNV-1a discriminant is computed from the fully-qualified type name,
   avoiding the need for a separate IDL registry at emit time.

3. **Guest-side size checks before syscall** — The `emit_event!` macro checks the serialised
   size before invoking `sys_emit_event`. This gives the guest program an early, actionable
   error (`EventTooLarge`) rather than a cryptic runtime rejection.

4. **`no_std` SDK** — The guest crate has no `std` dependency, making it compatible with the
   zkVM guest environment. The `std` feature gate enables the decoder and runtime modules for
   off-chain use.
