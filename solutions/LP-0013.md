# Solution: LP-0013 — Token Program Improvements: Authorities

Implementation of LP-0013: mint authority lifecycle for the LEZ Token program, with a proven on-chain semantic deployment under `RISC0_DEV_MODE=0`.

**Repository:** <https://github.com/Tranquil-Flow/lp0013-token-suite>

**Narrated demo video:** <https://youtu.be/3hQd2G8O-UM>

## Summary

This submission ships:

- An offline, runtime-agnostic authority crate (`admin-authority-core`) and pure state-transition layer (`mint-core`) — 31 unit + 3 example tests, no SPEL/LEZ runtime dependency.
- A SPEL guest (`spel-spike/admin_authority_guest.rs`) that ports the same authority semantics into the RISC0/LEZ account adapter — deployed to the live local LEZ sequencer and exercised over four real transactions.
- Live on-chain four-transaction lifecycle with txhashes captured (deploy + `create_mint` + `mint_to(100)` + `set_mint_authority(None)` + post-revoke `mint_to` rejection), independently re-verified ~22 minutes later with a fresh `set_mint_authority` rejected on chain at `Program error 2008: authority has been revoked` — the canonical `require_authority` panic from the guest body, observed live on the sequencer.
- Per-operation Risc0 zkVM executor time captured from the live sequencer log: `create_mint` 8.38 ms, `mint_to` 7.58 ms, `set_mint_authority` (rotate/revoke shares one code path) 6.76 ms. Rejected post-revoke operations cost ~50% less (4.21–4.43 ms) — the deterministic-rejection guard halts execution before any account writes, visible in the CU profile.
- Dual IDL evidence: hand-written canonical (with discriminators, declared errors, expanded `Option<T>` and nested account bodies) and real `spel generate-idl` output checked in alongside, against the same LEZ pin (`v0.2.0-rc1`) and SPEL revision (`ed3bbedb4b684645da05455d30a4a0be7cc4dfe0`) LP-0017 uses.
- Three runnable evaluator examples (variable supply, fixed supply, config-PDA-gated) — the third demonstrates the RFP-001 reusable authority library pattern offline.

## Architecture decisions

1. **Single-`None`-represents-revoked encoding.** `Option<[u8; 32]>` for `current_authority`; `None` means permanently revoked. No separate "is_revoked" flag, no two-state model. Audited and on-chain confirmed.
2. **Offline-first proof model.** The canonical authority semantics are proven in pure Rust (`mint-core`, 7 unit tests). The SPEL guest is a separate evidence layer demonstrating the same semantics survive translation to the RISC0/LEZ account adapter.
3. **Hand-written canonical IDL + real SPEL-generated alongside.** The canonical hand-written IDL is the documented superset (discriminators, declared errors, execution block, expanded Option/nested types). The real SPEL-generated artifact is checked in alongside as additive evidence the same instruction surface re-emerges from the real tool.
4. **`examples/config-pda-gated` as the RFP-001 demonstration.** Derives a deterministic config-PDA authority and proves that only the matching gate can mint before revocation — the canonical RFP-001 admin-authority-lib pattern.

```bash
# 2. Live LEZ semantic proof (host-only, requires lgs + cargo-risczero + spel):
#    See spel-spike/README.md for the full scaffold-and-deploy walkthrough.
#    All txhashes from the 2026-05-18 release-candidate rerun are captured
#    in docs/LEZ_PROOF_LOG.md.
```

## Known limitations

The live SPEL guest is a separate evidence layer, not the production tested implementation. Authority semantics are canonical in `mint-core`; the guest is structurally aligned and on-chain-exercised, but daily test runs remain on the offline harness due to the macOS-arm64 RISC0 toolchain conflict documented in [`docs/SPEL_STATUS.md`](https://github.com/Tranquil-Flow/lp0013-token-suite/blob/main/docs/SPEL_STATUS.md).
