## Approach

Two-guest split. `multisig_verifier.bin` is a SPEL program that does only
accounting: it owns the multisig, proposal, marker, and treasury PDAs, and
never sees a secret. `membership_lez.bin` is a native LEZ membership guest:
it proves a leaf folds to the committed member root and produces the
nullifier, and runs only on the privacy path via a chained call. The
nullifier is H(proposal_ref, msk), so double voting is structural, not
countered: a second approval by the same member derives the same nullifier,
hence the same marker PDA, which the framework init guard refuses. The
threshold is the count of distinct nullifiers, so the on-chain record shows
that M was reached, never which members approved. Execution is a public
re-execution over the marker set and is unlinkable to any member account.

## Known limitations

Stated plainly now, updated as the close-out lands:

- The member leaf currently derives its npk with a submission-local prefix
  rather than LEZ's canonical `H("LEE/keys", msk, 7, ...)`. Either the
  derivation is aligned or the leaf is documented as a commitment to the
  member secret rather than to their live LEZ account; the choice is made
  and disclosed before review.
- Witness salts are generated from wall clock nanos plus a counter; the
  final build derives them from the OS CSPRNG.
- Config rotation (`superseded_by`) is reserved, not implemented.
