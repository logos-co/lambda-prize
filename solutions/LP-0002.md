# Solution: LP-0002 - LEZ-Quorum Private Threshold Treasury

**Submitted by:** FidelCoder

## Summary

LEZ-Quorum is a private threshold treasury for the Logos Execution Zone. An
M-of-N group can authorize transfers, membership rotations, and threshold
changes without publishing its member list or attributing approvals to named
members.

The credential-aware Risc0 circuit, SPEL gate, private LEZ transaction
composer, Rust SDK, CLI, complete generated IDL, and Basecamp native backend
are implemented and verified locally. A reproducible example completes program
deployment, treasury initialization, funding, private 2-of-3 approval,
execution, and final state reads against an LEZ v0.2.0 standalone sequencer.
Native and portable Basecamp LGX packages also build from a pinned Nix lock.
The implementation has not been deployed to a public LEZ testnet and is not
presented as production-ready or audited.

## Approach

The constitution stores one Merkle root over commitments to LEZ regular
private-account credentials. Each approval proves:

- control of an LEZ nullifier secret key and account identifier;
- membership of the derived account commitment under the active member root;
- a distinct proposal- and constitution-bound Quorum nullifier;
- a proposal-scoped credential binding for the outer private account; and
- satisfaction of the threshold and action policy.

The gate accepts the multisig, proposal, and authorized private credential
accounts. It checks the credential bindings, verifies the threshold receipt as
a Risc0 assumption, updates the proposal, and preserves LEZ positional account
semantics. The gate also binds proposal ownership, proposal ID, constitution
version, recipient, vault PDA, transfer tier, and amount cap.

The composer verifies the stored threshold artifact against the pinned image,
attaches the receipt while proving the gate, passes the gate receipt to the LEZ
privacy circuit, and builds a signed `PrivacyPreservingTransaction`. Its
all-features build includes sequencer submission, confirmation polling by
transaction hash, and public account reads. The `local_lez_e2e` example deploys
the gate, initializes a token and signed treasury PDA, funds the vault,
proposes, privately approves, executes, and verifies chain state.
The integration test proves that credential IDs are absent from the final
message's public account list.

Membership rotation is threshold-authorized and atomic. The local workflow
retains replacement credentials privately, rejects early activation, retires
the old root, and demonstrates that old credentials fail while replacement
credentials can authorize new proposals.

The IDL generator emits all five instruction layouts, including
`InitializeVault`, plus state accounts, custom types, and errors 4001-4017.
Generated client and FFI code plus instruction codec round trips are tested.

The Basecamp module contains QML views, Qt Remote Objects definitions, CMake,
pinned Nix packaging, and a native QProcess backend. The backend uses an
operation allowlist, invokes no shell, forces non-dev proving mode, protects its
working directory, streams output, supports cancellation, and enforces a
timeout. Native and portable LGX variants build successfully, and the
module-builder standalone host loads the Quorum UI plugin headlessly.

## Privacy Boundary

Private inputs include LEZ nullifier secret keys, private credential account
IDs, the enrolled member list, Merkle positions and paths, and credential
post-state contents. Proof artifacts contain proposal-scoped credential
bindings rather than stable account pseudonyms.

Public state includes multisig and proposal IDs, constitution policy, member
root and count, proposal actions and status, approval count, Quorum
nullifiers, and governance changes. Network-level sender anonymity has not been
established on a public testnet; local execution does not establish public
network metadata behavior.

## Reproduction

```bash
git clone --branch v0.2.0 --depth 1 \
  https://github.com/logos-blockchain/logos-execution-zone.git
git clone https://github.com/FidelCoder/LEZ-Quorum.git

cd LEZ-Quorum
cargo fmt --all -- --check
RISC0_DEV_MODE=1 cargo check --workspace --all-targets --all-features
RISC0_DEV_MODE=1 cargo clippy --workspace --all-targets --all-features -- -D warnings
RISC0_DEV_MODE=1 cargo test --workspace --all-features
RISC0_DEV_MODE=1 ./scripts/demo.sh

# Terminal A: local LEZ v0.2.0 sequencer
cd ../logos-execution-zone
RISC0_DEV_MODE=1 just run-sequencer standalone

# Terminal B: use a fresh identity seed for a persistent chain
cd ../LEZ-Quorum
RISC0_DEV_MODE=1 cargo run -p quorum-composer --features network \
  --example local_lez_e2e -- http://127.0.0.1:3040 151

cd apps/basecamp-quorum
nix build .#generate .#lib .#lgx .#lgx-portable

cd ../..
RISC0_DEV_MODE=0 \
  cargo run -p quorum-prover --example prove_threshold --release
```

See the repository README and `docs/DEPLOYMENT.md` for the integration and
deployment boundary.
