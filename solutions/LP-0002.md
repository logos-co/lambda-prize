# Solution: LP-0002 - LEZ-Quorum: Private M-of-N Multisig

**Submitted by:** FidelCoder

## Summary

LEZ-Quorum is a private M-of-N multisig primitive for LEZ. Members hold
shielded accounts; approvals are ZK threshold proofs; proposals, approvals,
and rotations leave no public trace of who voted. On-chain state records only
that a threshold was met and a nullifier set — never which members approved,
and not even *whether* the member set changed.

Beyond the LP-0002 core, LEZ-Quorum ships two differentiators the static-set
competitors do not: **shielded member rotation** (a threshold-approved
constitution update that revokes the old member set and commits a new one as a
single new root) and **tiered spending** (per-category thresholds and amount
caps, with categories kept as commitments rather than plaintext).

## Approach

A member approves a proposal by producing a Risc0 threshold proof over the
shielded-account commitment, a Merkle membership path against the current
member root, the proposal ID, and a **version-bound nullifier**
`nullifier = H(member_secret, proposal_id, constitution_version)`. The
on-chain SPEL verifier (`quorum-gate`) verifies the receipt against a pinned
image ID and records only the nullifier set. A nullifier cannot repeat
(double-vote prevention, error `1005`); after a rotation, the constitution
version advances so every old member's nullifiers are structurally invalid.

The LEZ account-model constraints are handled by `crates/lez-compat`: the
v0.3 commitment format, shielded-account nonce rules, and `program_owner`
checks are encoded once and reused by the circuit and the program. Rotation
is atomic — the old root is retired in the same proposal that commits the new
root, so a departed member's key can never approve again.

## FURPS Self-Assessment

### Functionality

Quorum covers multisig creation, shielded M-of-N approval, tiered spending,
threshold-approved member rotation, partial-approval resume, and nullifier
double-vote prevention. The CLI, SDK, SPEL program, and Basecamp module
exercise every stage of the lifecycle.

### Usability

The CLI (`create / propose / approve / execute / reject / info / new-root`),
Rust SDK, Basecamp QML module with local build instructions, and the demo
script cover the member and operator flows. Typed errors and
`docs/ERROR_CODES.md` make failure diagnosis deterministic.

### Reliability

Version-bound nullifiers make rotation revocation atomic and restart-safe;
partial approvals resume from the on-chain nullifier set; the verifier
returns deterministic documented errors; the evidence pipeline is regenerable
via `scripts/regenerate-evidence.sh`, so testnet resets cannot kill the
submission. Spending caps are re-derived from constitution state at
propose/check time so a caller can never inflate a cap (error `4011`), the
treasury vault PDA is validated at execute (`4012`), and a consistency test
pins the proof image ID so verifier/prover drift cannot silently recur.

### Performance

Real 2-of-3 threshold proof: ~446 s generation (16 cores, regenerated
2026-08-04), 224,346-byte receipt, pinned image ID. Proof time is dominated
by SHA-256 Merkle-path evaluation; the **aggregated single-proof mode is
shipped** (`quorum approve-all` / SDK `Multisig::approve_many`) and amortizes
the fixed proving overhead across M approvals. The network currently omits
transaction CU metadata.

### Supportability

The workspace separates types, LEZ compatibility, circuit, prover, gate-core,
SPEL program, SDK, CLI, and Basecamp concerns. ADRs (ADR-0001..0006),
`BUGS_FILED.md`, security assumptions, and known limitations are documented.

## Privacy And Security

**Hidden:** member identity and membership set; nullifier secrets; Merkle
paths; proposal approvers; rotation history (only new roots are visible).

**Public:** proposal action (per LP-0002 scope, content is not hidden);
nullifier set; member root; constitution version; tiers (committed).

LEZ-Quorum has not received an independent security audit; the circuit is
kept small by design to minimize the audit surface.

## Impact

Quorum turns a public multisig into a privacy-first governance primitive:
DAOs, treasuries, and protocol governance can change membership and
thresholds without publishing their org chart, and spending policies can be
tiered per category while every category stays committed.
