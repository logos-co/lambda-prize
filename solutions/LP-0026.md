# Solution: LP-0026 — Agora native forum for Logos Basecamp

**Submitted by:** @stevancarlon

Verification limits are stated below; this submission does not claim every prize criterion has been met.

## Summary

Agora is a native, local-first forum for Logos Basecamp. C++17 and Qt/QML provide a compact discussion interface; SQLite keeps identities, drafts and posts on the user's device. Logos Delivery exchanges signed posts and retrieves missed history. Logos Storage exchanges content-addressed attachments.

## Approach

Native Qt integrates with Basecamp's module API and avoids a separate browser-hosted application server. SQLite makes failed sends and drafts durable. Backend validation, signing, persistence and media handling are separate from QML presentation. The early React prototype is historical; it is not the shipped app. Delivery and Storage provide peer transport and content addressing without a centralized application backend. Public discussion posts are not end-to-end encrypted; anonymous display does not promise network anonymity.

## FURPS Self-Assessment

### Functionality

Agora supports boards, threads, replies, quote references and previews, local search, attachments, multiple identities, alias/public-ID/anonymous display, and identity rotation. Logos Delivery transports signed posts and retrieves missed history; Logos Storage handles content-addressed attachment bytes. Public text receipt is verified between profiles on one host, and an independent hosted reader verified attachment sizes and hashes. Testnet 0.4 operation and cross-machine Delivery/Store messaging remain unverified.

### Usability

The native Qt/QML interface provides boxed posts, attachment previews, persistent drafts, inline video, keyboard submission, quote navigation and light/dark themes. Installation instructions and a module catalog are provided for Basecamp. The narrated walkthrough demonstrates the UI workflows. Broader non-expert usability evaluation remains outstanding; releases are unsigned alpha builds and media support uses a separate runtime.

### Reliability

SQLite transactions preserve posts and drafts across restarts. The backend validates signatures and payloads, deduplicates received messages, retains failed sends for retry, and bounds recovery requests. Only a matching Delivery messageSent event marks a post sent. Private relay/Store restart tests and public attachment retrieval checks are linked below. Sustained public reconnect testing and cross-machine Delivery/Store acceptance remain unverified.

### Performance

The sender permits one message in flight, paces sends and backs off retries. Payload limits and paginated feed/history queries bound work and network traffic. These controls are implemented and covered by local checks; no sustained production-scale throughput or memory benchmark is claimed.

### Supportability

The implementation is C++17/Qt/QML with SQLite, with backend validation and persistence separate from the UI. Source, installation instructions, protocol documentation, release checksums and CI workflows are public. Original code is available under both the MIT License and Apache License 2.0. The local verification report records 26 backend and 67 QML checks; current hosted results are linked in the checklist, including pending desktop checks. Network dependencies are not available on every packaged desktop target.
