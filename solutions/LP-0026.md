# Solution: LP-0026 - Forumer: a private, serverless forum for Logos Basecamp

**Submitted by:** Bristin Borah ([@bristinWild](https://github.com/bristinWild))

## Summary

Forumer is a forum app for Logos Basecamp with no server anywhere. Topics and replies travel over **Logos Delivery**. Identities, the post log and unsent posts stay on the user's device. A newcomer still gets the whole forum: from the peers it can reach, and from the network's own store nodes when nobody else is online.

Each account is one master key behind a password, backed by a 24-word recovery phrase. Other people only ever see **personas** derived from that key, and no two personas can be linked to each other. For every post the author chooses to sign with a persona, add an alias, or post anonymously. They can keep one persona, rotate it by hand, or get a fresh one for every post.

Since 0.2.3, people can also create **private forums** joined by invite link, sealed end to end, and attach **images**, stripped of metadata, encrypted and stored in **Logos Storage**, with previews that show instantly.

Forumer installs in one step from its own module catalog, built with the official release template. CI is green on the default branch. The narrated demo walks through the whole flow, from catalog install to every feature.

## Approach

### Architecture

Forumer is a `ui_qml` Logos module built with logos-module-builder 0.3.2. It has two parts:

- **`forumer_core`** is a C++20 library with no UI or Qt dependency. It holds the forum logic:
  - identities, the vault and the recovery phrase;
  - signed post envelopes and proof of work;
  - the SQLite post log and outbox;
  - sync rules, thread placement and flood limits.

  It has 150 unit tests and can be reused by any other Logos app that needs signed, rate-limited public posts.
- **The module** is a thin backend plus a QML view. The backend wires the core to `delivery_module` (v0.3.0) and `storage_module` (v3.0.0), runs the timers and exposes state to the view over Qt Remote Objects.

### Why the Logos stack fits

The point of the prize is speech without someone in the middle who can be pressured. A centralised forum keeps an account table, IP logs and a delete button, and all three are the attack surface. Forumer runs without any of them:

- **Logos Delivery** gives a relay network that no single party runs. Its store nodes give newcomers history without Forumer running an archive.
- **Basecamp** gives one-click installs, dependency resolution, and an intent system for shareable links that don't route through a web server.

What a centralised build would lose:

- unlinkable personas, because the server sees every login;
- resistance to takedown;
- the guarantee that "who replied to whom" is worked out only on each reader's own device.

### Key decisions, and what was tried and dropped

- **Plain relay plus digest repair, not reliable channels (SDS).** SDS's causal ordering held later messages back until earlier ones arrived. When a post was lost, its re-sent copy was held back as "missing dependencies" too, so one lost post blocked repair. Instead, peers exchange short digests of the post ids they hold and re-send what is missing. The SDS path is kept behind a switch.
- **History from store nodes, with a 24 h fallback.** On joining, Forumer queries the logos.dev fleet store nodes for the forum topic, asking for 30 days first. Some nodes reject anything over 24 h (`BAD_REQUEST: time range exceeds 24h`); for those it asks for one day. Older history comes from peers a week at a time, back to the oldest post anyone holds.
- **History over Delivery, not Logos Storage, for now.**
  - On storage_module v2.1.2, a node behind a home router never announced what it held, so files shared from laptops couldn't be found.
  - On v3.0.0, sharing works in both directions between two nodes, at 73–83 s per fetch.
  - That is too slow for message history, so history stays on Delivery. Storage carries images instead (0.2.3), with holder hints over Delivery to make fetches fast.
- **Own keys rather than `keystore_signer`.** Forumer needs many personas derived from one master key, and needs to verify signatures as well as make them.
- **Local SQLite rather than Logos SQL.** The post log is private to the device and holds the outbox; Logos SQL runs as a blockchain zone, and blockchain is out of scope for this prize.
- **One content topic for all domains** (`/forumer/3/public/proto`). Domains are filtered on the device, so the network can't see which ones a person reads.
- **Hourly limits counted on author time**, so a peer catching up after a day offline isn't mistaken for a flood.
- **Shareable links without a lookup.**
  - A link carries only the post id and its day. A reader who doesn't hold that thread asks for the whole range of days around it, the same request as ordinary history sync.
  - So nobody learns which thread was opened.
  - Links are a Basecamp intent (`forumer.open`) declared in `metadata.json`.
- **Problems found in Basecamp itself:**
  - `QRegularExpression` crashed inside Basecamp's hardened runtime on macOS, so it was replaced with plain character checks.
  - `connectionStateChanged` only fires on transitions. When Basecamp's node was already up, the app showed "waiting for peers" forever, so Forumer now also asks for the connection state every 15 s.
 
### Added in 0.2.3

- **Private forums.** A forum is a 32-byte key with its own topic (`/forumer/3/pf-<id>/proto`). Create one, share an invite link, join from the link. Posts are sealed on the wire and at rest with separate subkeys, so relays, store nodes and anyone holding the database file see only ciphertext. Late joiners repair history through the 48 h digest and the store archive.
- **Images.** Up to 4 per post. Each is rebuilt from raw pixels, so EXIF/GPS/ICC data never leaves the machine, then encrypted (convergent; forum key mixed in for private forums) and stored in Logos Storage. The post signs `{cid, mime, size, sha256}`. A signed, sealed preview travels with the post over Delivery, so pictures show the moment a thread opens; the full image follows from a holder found by a hint over Delivery and is checked against the signed hash.
- **Security review.** An independent review of 0.2.2 reported 18 findings; 17 are fixed in code and confirmed in a follow-up review of 0.2.3; one (catalog install timeout) is documented with a workaround.

## FURPS Self-Assessment

### Functionality

**Supported:**
- several accounts per device;
- persona, alias and anonymous posting, with keep / manual / auto rotation;
- topics with up to 3 domains, follow, and starter domains;
- two-level replies;
- a Markdown editor with toolbar and preview;
- ⌘K search;
- a replies inbox with unread badge and notices;
- My posts;
- shareable `basecamp://` links to threads and domains;
- outbox and retry;
- offline catch-up, store-node history and full history;
- flood control;
- backup, restore, password change, lock and account removal;
- network choice (logos.dev, or logos.test with RLN);
- private forums: create, invite link, join, leave; sealed on the wire and at rest;
- images: up to 4 per post, metadata stripped, encrypted in Logos Storage, signed previews, re-host and auto-load settings.

**Limitations:**
- No private messages, mute or hide yet; the Chats screen says so.
- Logos Chat is not used yet; private forums use Delivery with Forumer's own sealing.
- Full images need a running storage node (it starts after unlock, about 1–1.5 min the first time); previews don't.
- logos.test needs an RLN membership to start.
- Posts can't be deleted from the network. That is deliberate in a serverless design, but worth stating.

### Usability

- **Install:** one catalog link in Basecamp; dependencies resolve automatically.
- **Onboarding:**
  - account name and password, then the recovery phrase, then home;
  - "there is no password reset" is stated up front;
  - a new account sees the existing forum within seconds.
- **Navigation:**
  - sidebar with home, replies, my posts, missed, followed domains, profile & personas, settings, backup & restore;
  - the connection state is always visible.
- **Feedback:** every post shows its delivery state, quota is shown before it runs out, errors are in plain words, and empty states explain what will appear.
- **Look:** a night-city theme, light and dark, with OFL fonts bundled.
- **Private forums and images:** a Forums section in the sidebar with create/join sheets; an "attach images" button or drag and drop in the composer, with upload progress, retry and remove per image.

### Reliability

**Sending:**
- The outbox is written before sending.
- Retries back off from 15 s to 5 min and survive restarts.

**Receiving:**
- Digest exchange repairs gaps from any peer holding a post.
- On joining or reconnecting, Forumer catches up on 48 h, queries store nodes (with the 24 h fallback), then fetches older weeks from peers.
- Forumer asks for the connection state every 15 s, so status can't get stuck when Basecamp's node was already running.

**Integrity:**
- Every post is a signed envelope.
- Invalid signatures, failed proof of work, over-limit authors and oversized messages are dropped by every peer.
- Images are opened only if they match the hash, size and type the author signed; previews must carry the author's signature over the post id and index.
- A stalled image download is restarted once; previews never depend on Storage.

**Untrusted input:**
- Markdown is rendered without HTML or remote images, so reading a post can't leak an IP address to its author.
- Link payloads are validated.

### Performance

- **Delivery:** a post appears on another node within seconds on logos.dev.
- **Proof of work:** 16 bits for signed posts (a fraction of a second); 20 bits for anonymous ones (about a second).
- **Store-node history:** 100 messages per page, node by node until one answers.
- **Network budget:**
  - per persona, at most 10 topics and 60 replies per hour;
  - never-seen keys share a budget of 60 posts a minute (bursts of 120);
  - re-sends are capped at 240 per minute;
  - posts and messages have size caps.
- **Images:** previews arrive with the post (≤ 96 KB, shown in under 50 ms locally); the full image downloads in seconds once a holder is found through a hint (about 4 s in two-node tests, against 70–115 s without hints).

### Supportability

- **Tests:**
- 150 unit tests in `forumer_core`, also run under ASan/UBSan: crypto, vault, mnemonic, identity and rotation, account store, envelopes and proof of work, post log and outbox, sync, history, thread placement, inbox, flood, private forums, media sealing and previews.
  - Run them with `./scripts/test-core.sh`.
  - End-to-end runs use `./scripts/two-instances.sh` (isolated data folders via `LOGOS_USER_DIR`).
- **CI:** GitHub Actions on every push runs the unit tests, then the module build on Linux and macOS, using the Logos Nix cache. A separate catalog repo releases builds and rebuilds the index.
- **Debugging:** backend logs are prefixed `[forumer backend]`. Environment switches: `FORUMER_NETWORK`, `FORUMER_STORE_PEERS`, `FORUMER_NO_STORE`, `FORUMER_DEV` (storage probe), `FORUMER_LOG_FILE` (backend log to a file), `LOGOS_USER_DIR`.
- **Docs:** README with 15 sections: features, quick start, usage, architecture, identity, posts, sync, flood control, threat model, design decisions, layout, testing, requirements, roadmap.
