# Solution: LP-0008 — Autonomous AI Agent Module

**Submitted by:** retraca (Gonçalo Traça)

## Summary

Two Logos Core universal modules (Qt, C++/Rust) that together form an autonomous AI agent with a shielded LEZ wallet identity:

1. **`lez_wallet_module`** — a new Logos Core universal module that did not previously exist. Wraps `lez-wallet-core` (Rust, FFI over `nssa` / `wallet` / `bedrock_client`) to expose the full LEZ shielded wallet and program interface to any Logos module via `LogosAPI`. Nine wire methods: `ensure_account`, `npk`, `balance`, `history`, `sync_private`, `send`, `program_query`, `program_call`, `program_deploy`.

2. **`agent_module`** — autonomous agent built as a pure C++ Logos Core universal module. Skill dispatcher with spending-threshold gate (per-tx and per-period limits with owner override), A2A task coordination (A2A spec v0.2 JSON-RPC over Logos Messaging), owner channel over E2E `chat_module` conversation, and a pluggable inference adapter interface. 17 named skills across storage, messaging, wallet, programs, A2A, and meta namespaces.

Pre-built Mach-O arm64 bundles are included; the Rust core builds with `--features lez-bridge` against the `lez-build` workspace.

## Approach

**Identity model:** On first call to `ensure_account`, a BIP39 mnemonic is generated and an NSK (NullifierSecretKey) is derived from it. The NSK is encrypted at rest under the owner's passphrase (AES-256-GCM, Argon2id key stretch). The NPK (NullifierPublicKey) is published in the A2A Agent Card as `x-lez-identity.npk`. No custodian; the NSK never leaves the node.

**Module architecture:**

```
Owner (Logos Basecamp)
  | E2E chat_module conversation (owner channel)
  v
agent_module (universal C++)
  | spending gate (per_tx_limit / per_period_limit / period_seconds)
  | A2A task lifecycle
  +--> lez_wallet_module  (new — shielded wallet + programs)
  +--> chat_module        (Logos Core platform)
  +--> delivery_module    (Logos Core platform)
  +--> storage_module     (Logos Core platform)
```

**`lez_wallet_module` build:** Rust crate (`lez-wallet-core`) compiled as `[cdylib, staticlib, rlib]` with `--features lez-bridge`. `cbindgen` generates `lez_wallet_ffi.h` with `extern "C"` guards. The Qt module uses `logos-cpp-generator` (dual-pass: module glue + SDK helpers), links `logos-cpp-sdk::logos_sdk`, and wraps every async Rust call in a single-threaded Tokio runtime exposed over the C FFI.

**`program_call`:** fetches account nonces, builds `nssa::public_transaction::Message::new_preserialized(program_id, account_ids, nonces, instruction_data)`, signs with `WitnessSet::for_message`, submits as `NSSATransaction::Public`.

**`program_deploy`:** reads binary, derives RISC-V `ProgramId` via `Program::new(bytecode)?.id()`, builds `program_deployment_transaction::Message::new(bytecode)`, submits as `NSSATransaction::ProgramDeployment`, returns hex program ID.

**Local chain:** `WalletConfig::default()` points to `http://127.0.0.1:3040`. Run `docker-compose up -d` in `lez-build` before calling any wallet methods.

## Known gaps

- A2A identity binding: the Agent Card publishes the NPK; deterministic derivation of the chat-module `introBundle` from NSK is a known gap (LEARNING.md §9/§10).
- Inference adapter: the `InferenceAdapter` interface is intentionally unbound — LLM integration is operator-supplied and out of scope for this submission.
- Live chain test: not completed due to colima filesystem corruption blocking `docker-compose up`. Implementation follows lez-build transaction formats from source.
