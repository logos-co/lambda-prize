# Solution: LP-0008 — daemon-ai on Agora

**Submitted by:** Beach-Bum

## Summary

A Logos Core module that runs an autonomous AI agent with native access to the full Logos stack: a shielded LEZ wallet (Groth16 ZK proofs), Logos Storage, and Logos Messaging (Waku). The agent has its own ZkPublicKey identity and funds, communicates with its owner via an E2E encrypted channel, and coordinates with other agents via the A2A v1.0.0 protocol. Deployed with a single CLI command.

21 composable skills across 5 categories. 3 end-to-end demos. 5 agents deployed on testnet. All demo operations run against real services — no mocks.

## Approach

### Architecture

The agent is packaged as a Logos Core module with two components:

1. **C++ backend** (`logos-agora-module/`) — loaded by the liblogos kernel via Qt Remote Objects (`agent/remoteobjects/DaemonAgent.rep`). Runs AgoraCore, which orchestrates DaemonAIService, MessagingService, BlockchainService, and StorageService.
2. **QML frontend** (`logos-agora-ui/`) — hosted by Logos Basecamp. 6 views: chat, dashboard, wallet, skills, owner channel, agora marketplace.
3. **Python agent framework** (`agent/`) — standalone agent nodes that participate in the marketplace without Basecamp. This is the primary runtime used in the demo.

### Identity and wallet

Each agent holds its own shielded LEZ account identified by a ZkPublicKey. The wallet (`agent/core/daemon_wallet.py`) enforces a spending policy: per-transaction limit (default 10 NOM) and daily cap (default 100 NOM). Transactions exceeding the threshold are held for owner approval via the encrypted owner channel. An emergency freeze kills all outgoing transactions until the owner unfreezes.

All on-chain transfers use the logos-blockchain-node's shielded UTXO model with Groth16 zero-knowledge proofs — balances and transaction amounts are hidden from observers.

### LLM inference

The agent uses a pluggable inference backend with automatic fallback:

```
daemon-ai C++ runtime (localhost:8765)
    -> Ollama local inference (localhost:11434)
    -> OpenAI-compatible API
    -> Mock (deterministic responses for testing)
```

The demo runs against Ollama with llama3.2:3b — fully local, no API keys, no cloud calls. daemon-ai (Mamba SSM architecture, C++ runtime) is the target production backend.

### Agent-to-agent coordination (A2A v1.0.0)

Agent coordination follows the A2A protocol (Linux Foundation). Agent Cards declare identity, skills, input/output schemas, and LEZ pricing. Task interactions follow the A2A lifecycle: SUBMITTED -> WORKING -> INPUT-REQUIRED -> COMPLETED/FAILED.

Logos Messaging (Waku) replaces A2A's HTTP transport. LEZ token transfers fill the payment gap A2A leaves open. The result is A2A-compatible agent discovery extended with payment and privacy.

### Skill SDK

Skills are defined as discrete, composable units registered in a SkillRegistry (`agent/skills/base.py`). Third parties add skills by implementing the Skill interface and calling `registry.register()` — no core module modification required.

### Owner channel

The owner channel (`agent/core/owner_channel.py`) provides E2E encrypted communication between the agent and its owner over Logos Messaging. Above-threshold transactions trigger an approval request; the agent waits for owner confirmation before submitting. Timeout and retry logic ensures transactions are never silently dropped.

## FURPS Self-Assessment

### Functionality

21 skills across 5 categories. All default skills from the prize spec are implemented: storage (upload, download, list, share), messaging (send, join, create_group), blockchain (wallet.balance, wallet.send, wallet.history, program.query, program.call, program.deploy), agent coordination (card, discover, task, subscribe, cancel), and meta (skills, status, configure).

The A2A transport binding uses Logos Messaging content topics for discovery (`/agora/1/capabilities/json`), intents (`/agora/1/intents/json`), negotiation, and delivery confirmation. LEZ payments are triggered within the A2A task lifecycle.

Three LSSA smart contracts (Rust): identity registry with staking, trustless escrow with hash-committed delivery, and EMA-based reputation scoring.

### Usability

Single CLI command deployment. The `agora_cli.py` tool covers the full lifecycle: deploy, fund, status, skills, invoke, config, freeze, unfreeze, card. Skill invocations return structured JSON with timing metadata.

### Reliability

Wallet state is persisted via JSONL audit log. Spending policy enforcement is checked before every outgoing transaction. The emergency freeze flag immediately blocks all outgoing transfers. Owner channel messages include request IDs for idempotent retry.

### Performance

ZK proof generation for token transfers takes 1-3 seconds on the standalone node (Groth16 circuits). LLM inference with llama3.2:3b generates 50-200 tokens in 3-10 seconds depending on prompt complexity. Waku relay publish/read is sub-second.

### Supportability

Code is organized into clear modules: `agent/core/` (wallet, keystore, owner channel, autonomous daemon), `agent/skills/` (5 skill modules), `agent/logos/` (3 Logos integration clients), `agent/bridge/` (HTTP bridge for QML), `contracts/` (3 Rust contracts). 7 documentation files covering architecture, protocol, contracts, agent guide, skill SDK, submission details, and demo script.
