# Solution: LP-0012 — Structured Event/Log Mechanism for LEZ Programs

**Submitted by:** pramadanif

## Summary

This submission implements a complete structured event system for Logos Execution Zone (LEZ) programs. Programs emit typed, Borsh-encoded events via `emit_event(...)`. A runtime adapter (`execute_program`) automatically preserves events on both success and failure paths by framing them into the RISC0 journal before a panic unwinds. Clients retrieve and decode events with a CLI/library, and a reference indexer shows how explorers can consume them.

**Key differentiator:** minimally invasive framed transport (`LEZE` magic prefix) that does **not** require rewriting LEZ core `ProgramOutput` / `TxReceipt` structs. Sequencer-side adoption is a small `parse_journal` slice before normal journal handling.

## Approach

### Why LEZ needs this

LEZ programs run inside Risc0 zkVM. On panic, journal output is normally lost — developers and indexers get no structured explanation of *why* execution failed. LP-0012 requires events that remain available even when the transaction fails.

### Event model

```rust
pub struct EventRecord {
    pub program_id: [u8; 32],  // runtime-enforced attribution
    pub sequence: u32,         // 0-indexed, monotonic per tx
    pub discriminant: u64,     // program-defined event type
    pub schema_version: u8,    // forward compatibility (v1)
    pub payload: Vec<u8>,      // Borsh-encoded fields
}
```

- **Encoding:** Borsh (already in LEZ workspace; deterministic; `no_std`-friendly)
- **Limits:** max payload 1,024 bytes; max 64 events/tx; max 65,536 total bytes
- **Errors:** `EventError` with stable codes `0xEE01–0xEE04` — never panic, never silent truncate

### Runtime adapter (failure-path survival)

Programs call `emit_event` into a thread-local buffer, and wrap logic in `execute_program(|| { ... })`:

1. On success: drain buffer → frame as `LEZE` → `commit_slice` → continue normal output
2. On panic: adapter `catch_unwind` → drain → frame → commit → `resume_unwind`
3. Host/sequencer runs `parse_journal` to slice the `LEZE` frame before parsing `ProgramOutput`

Events therefore survive state reversion. Developers do not manually `drain` before every panic site.

### Alternatives considered

| Option | Outcome |
|--------|---------|
| Extend `ProgramOutput` with `events` field | Rejected as primary path — large upstream blast radius |
| Manual drain-before-panic in every program | Rejected — leaks transport into app code; easy to forget |
| Framed journal + runtime adapter | **Chosen** — compatible, failure-safe, small sequencer diff |
| JSON payloads | Rejected — non-deterministic / verbose / poor `no_std` fit |

### Why Logos / LEZ fits

LEZ’s public/private execution split and Risc0 journal semantics make structured, privacy-aware events a natural client interface (debug UX, wallets, indexers) without putting sensitive private-state fields on-chain by default. Events are treated as **public** data; docs call out what is safe vs unsafe to emit under private execution.

## FURPS Self-Assessment

### Functionality

Typed emit API, Borsh wire format, decoder CLI, failure-path preservation via runtime adapter, reference indexer. Sequencer adoption is intentionally minimal (`parse_journal`) rather than a full LEZ fork rewrite.

### Usability

One call to emit; wrap program body in `execute_program`. CLI supports decode from tx/RPC and offline hex. Interactive web decoder provided.

### Reliability

Size limits return errors (no panic/truncation). Failure path commits framed events before unwind. Attribution: sequencer must overwrite `program_id` (documented; SDK alone cannot be trusted for attribution).

### Performance

Event buffer + Borsh overhead is negligible vs Risc0 proving time. Benchmarks and notes in `docs/benchmarks.md`.

### Supportability

Workspace layout, MIT license, CI, demo script, architecture docs, gap analysis, and runtime integration notes for LEZ maintainers.
