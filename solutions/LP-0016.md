## Approach

### Protocol Summary

Members register with a staked commitment `SHA256("forum/v1/commitment:" ‖ id_secret)`. Each post carries a Risc0 zkVM STARK proof that the author holds an `id_secret` whose commitment is a leaf of the current Merkle tree — without revealing *which* leaf. Posts from the same author are unlinkable until a slash.

At registration the member Shamir-splits their `id_secret` into M shares (K-of-M threshold) and commits each share on-chain. When K moderation certificates accumulate, any party submits a slash transaction: the registry verifies K×N Ed25519 signatures, reconstructs `id_secret` via Lagrange interpolation over GF(2⁸), verifies the commitment, and revokes the member.

All pre-slash activity (posts, votes, certificates) travels over the Waku relay mesh. Nothing hits the chain until revocation.

## Deliverables

### 1. Moderation Library (`moderation-lib/`)

Forum-agnostic Rust crate exposing:
- `identity::{MemberIdentity, split_identity, verify_share}` — key generation and Shamir split
- `membership::{prove_post, verify_post}` — Risc0 zkVM proof generation and verification
- `moderation::{draft_vote, aggregate_votes, verify_cert}` — N-of-M certificate construction
- `slash::{build_slash, reconstruct_and_verify}` — slash bundle construction and off-chain verification

The library makes no assumptions about forum content or structure. It operates on abstract content-hash identifiers. The application layer (CLI daemon, mini-app) uses it without modification.

### 2. Membership Registry LEZ Program (`registry-lez/`)

On-chain stateless program built on `nssa_core` from the real `logos-execution-zone` git repository. Instructions:

| Instruction | Description |
|---|---|
| `Initialize` | Create forum with moderators, K, N-of-M, stake requirement |
| `Register` | Add member commitment + Shamir commitments to registry |
| `UpdateMerkleRoot` | Update the Merkle root after registration batch |
| `SubmitModerationCert` | Record a moderation strike against a member_tag |
| `Slash` | Verify K certs + K shares, reconstruct identity, revoke |
| `RejectNullifier` | Reject a duplicate post nullifier |
| `VerifyPost` | Verify a zkVM membership proof for an anonymous post |

IDL: [`registry-lez/registry.idl.json`](../registry-lez/registry.idl.json)

### 3. ZK Membership Proof Circuit (`circuit/`)

Risc0 guest program (RISC-V, `risc0-zkvm = "3.0"`) that proves:
- `commitment = SHA256("forum/v1/commitment:" ‖ id_secret)` is a Merkle leaf of `merkle_root`
- Derives `member_tag` and `post_nullifier` deterministically
- Commits all public outputs as a Borsh-serialised `MembershipProof` to the STARK journal

Proof generation: **< 3 seconds** in `RISC0_DEV_MODE=1`; **~15 seconds** for a full STARK on a standard laptop (measured on M2 MacBook Pro: ~14.6 s wall-clock).

### 4. Logos Mini-App (`app/`)

React + TypeScript SPA with Logos Basecamp module descriptor (`app/module.json`). Tabs:
- **Create Forum** — deploy a new forum instance on LEZ with arbitrary K, N-of-M
- **Member** — keygen, register with stake
- **Post** — anonymous ZK proof generation and post submission
- **Moderation** — moderator key generation, vote casting, cert aggregation
- **Audit Trail** — view accumulated certs for any forum
- **Live Feed** — WebSocket stream of Waku-relayed posts/votes/certs

### 5. CLI Daemon (`cli/`)

HTTP daemon (`forum-anon daemon --port 3101`) bridging the browser to Risc0 zkVM. Also exposes:
- `GET /waku-posts` — fetch posts from Waku relay
- `GET /ws` — WebSocket live feed polling Waku topics every 2 s
- Full on-chain transaction endpoints: `/deploy-forum`, `/register-onchain`, `/submit-post`, `/submit-cert`, `/slash-onchain`

Waku integration: publish/subscribe on topics `/forum-anon/1/{posts,votes,certs}/json`. Set `WAKU_NODE_URL=http://localhost:8645` to connect.

### 6. Logos Stack Usage

| Layer | Usage |
|---|---|
| **Execution (LEZ / NSSA)** | Registry program: membership, moderation cert storage, slash verification |
| **Messaging (Waku)** | All off-chain activity: post proofs, moderator votes, moderation certs |
| **Basecamp** | Mini-app descriptor (`module.json`) with daemon launch config |
| **Risc0 zkVM** | STARK membership proofs (unlinkable posts) |

## Two Testnet Forum Instances

Both deployed on LEZ standalone sequencer (`sequencer_service --features standalone` on port 3040).

| Instance | forum_id | K (strikes) | N-of-M | deploy_tx |
|---|---|---|---|---|
| Instance A | `80fd325d6506cce3bdf7bd6fbb7716d93acc65a7cb229f6a97d79ac12585296d` | 3 | 2-of-3 | `5151ac9c722d6423...` |
| Instance B | `eddca865bf87fbb34ed0b2c407f7fc4921d6fb08b5fdcbb6f842536737d190a8` | 5 | 3-of-5 | `34b37e3d108170ae...` |

**Run testnet deployment:**
```bash
# Start LEZ sequencer
./target/debug/forum-anon daemon --port 3101 &

# Deploy forum A (lenient: K=3, 2-of-3)
curl -s -X POST http://localhost:3101/deploy-forum \
  -H 'Content-Type: application/json' \
  -d '{"threshold_k":3,"threshold_n":2,"moderators":["<mod1_pubkey>","<mod2_pubkey>","<mod3_pubkey>"]}'

# Deploy forum B (strict: K=5, 3-of-5)
curl -s -X POST http://localhost:3101/deploy-forum \
  -H 'Content-Type: application/json' \
  -d '{"threshold_k":5,"threshold_n":3,"moderators":["<m1>","<m2>","<m3>","<m4>","<m5>"]}'
```
